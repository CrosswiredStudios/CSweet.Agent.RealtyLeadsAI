# 0.3.0

Readable replies with deep links.

- Chat reply redesigned: one bold header line carrying everything the rows share (count, place,
  status, score range, county count), then a table of what differs — Address, City · County
  (state-wide only), Owner, Deceased (with date of death), Heirs (total · reachable), Score and an
  **Open ↗** link to `https://realtyleads.ai/leads/<leadId>`. Lead IDs no longer appear as text;
  each link is built by the agent from a validated UUID, never from provider text. Rows are shown
  highest score first, at most ten; the header says when more are in the brief.
- Addresses are shortened for reading (`2180.0 MANGRUM AVE, SACRAMENTO, CA, 95822-3962` →
  `2180 Mangrum Ave · 95822`); the brief keeps the raw value. All provider text stays escaped.
- The `[lead-brief:<id>]` marker is now the first line of the reply as a markdown link
  definition: invisible when rendered, still parsed by managers, and the target of the
  **Full brief** link (relative to the organization's Documents page).
- Lead records carry three optional fields from plugin 0.2.1 (`dateOfDeath`, `totalHeirs`,
  `contactableHeirs`); cells fall back to the name alone / `—` until the provider returns them.
- Brief document: readable table of every lead (sorted by score) above the per-lead details and
  the unchanged data block; lookup replies use the same compact form.
- No manifest, grant or protocol changes; plugin dependency remains `realtyleads` >= 0.2.0.
