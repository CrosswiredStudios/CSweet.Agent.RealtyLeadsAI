# 0.2.1

Grounding and parsing fixes found during installed acceptance with a small local model.

- A request that names a state in words ("any leads for New York") now grounds the abbreviation
  the model derives (`NY`) through a fixed US state table; a quoted city or county also grounds the
  inferred state. Previously only a literal abbreviation in the message was accepted, so most
  natural requests ended in the clarification reply.
- A chat limit above ten is clamped to ten instead of refusing the request; a limit below one is
  still refused. The limit cannot broaden what is read.
- The planner's answer is parsed from the first balanced JSON object, so code fences, `<think>`
  blocks and surrounding prose from small models no longer land on "clarify". The object is still
  capped at 4 KB and every filter is still grounded against the request.
- No manifest, grant or protocol changes. Plugin dependency remains `realtyleads` >= 0.2.0.
